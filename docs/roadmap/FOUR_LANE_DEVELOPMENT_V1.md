## Execution order: ready work, no four-lane wave barrier

Eligibility precedes priority: an owner-selected bounded outcome, exact qualified prerequisites, real authority, an available repository writer slot and resource/provider budget. Among eligible work, use this order:

1. Finish or unblock an active installer acceptance or safety-critical defect. A required producer handoff inherits the blocked outcome's priority. Deliver the exact test candidate/resources early; do not make native credential qualification wait for full installer acceptance.
2. Deliver the smallest qualified producer outcome that unblocks another active lane. Publish a versioned contract/evidence subset within the same vertical assignment, then continue its implementation/delivery; contract-only is not overall completion.
3. Protect source capacity for the explicitly selected Workspace foundation. Its own server, storage, UI shell and installed-wheel proof do not wait for the installer, a physical reboot, rich Forge Console or complete multi-Action execution.
4. Reduce a measured critical path or repeated AI overhead. EP can select context/isolation/ledger/deterministic-validation slices; Forge can select the parallel frontier or read-only project projection. Follow their existing dependencies, not just their family rank.
5. Select other ready product work by priority, comparable measured effort, ready-age and stable ID. Unknown effort is unknown, not zero. Do not promise a fourfold speedup or infer acceptance from PR count.

For Workspace integration, Forge's narrow `PRM-F-CONTRACT` / `PRM-F-PROJECTION` with the required HTTP gate can precede the whole project-loop family. Workspace can meanwhile deliver useful own behavior and honest UNCONFIGURED/UNAVAILABLE peer states. Real peer views wait for exact authenticated HTTP evidence. No imports, database access, peer CLI, File Inbox or fake live fallback.

The existing concurrency chain remains: Forge `PA-F0` enables EP `PA-E0`; EP `PA-E1/E2/E3` enable Forge `PA-F3`; EP `PA-E4` enables Forge `PA-F5`; EP `PA-EQ` joins Forge `PA-FQ`. Forge continues its independent `PA-F1/F2` work while EP implements its side. Do not replace these fine-grained gates with “finish all Forge, then all EP”, or treat four Codex chats as qualified runtime parallelism.

Workspace public packages/deployment contracts later feed a **separately selected** Forge Platform adapter. Workspace is not added to the current installer DoD. The current installer still requires all previously agreed install/update/preserve/restore/purge, exact multi-instance, provider/pairing, GUI/CLI, signing and live acceptance; it is not declared complete by shipping a download.

## Resource-constrained throughput

Four disjoint source writers may progress concurrently. One repository still has at most one mutating assignment; subagents do not create additional writers. Worktrees separate source changes but do not isolate shared OS state.

Use ordinary unprivileged/hosted CI for normal PR checks. Reserve the exact signing identity, privileged host target, test namespace or reboot window only for its real use. At most one privileged mutation per shared host and one user of a signing identity at a time. CPU-heavy local build/test slots and shared model/token limits must be measured and configured; four lanes are not evidence of enough capacity. Source editing and independent tests need not hold the whole Mac.

Avoid hold-and-wait: do not retain an unrelated source or signer reservation while awaiting an external gate. Uncertain effects retain their exact hold until reconciled. A source boundary may be released only with an explicit clean checkpoint and two-sided transfer where another lane owned it; no timeout or empty PR list grants ownership. All affected lanes acknowledge a shared host window, not merely two named legacy lanes.

Required Quality/Security reviewers may run independently and read-only on the same immutable candidate when capacity and owning policy allow it. A changed SHA invalidates applicable evidence. Use deterministic tools for eligible deterministic validation instead of another LLM reasoning turn; preserve full mandatory role contracts, policy and coverage. Optional specialists need a concrete consumer and expected benefit. Do not lower model/assurance quality without qualified owning policy.

Measure accepted vertical outcomes and closed acceptance gates per elapsed time, blocked time by owner, first-pass acceptance, rework and cost per accepted outcome. PRs/LOC/tokens are secondary diagnostics. This policy is a practical heuristic, not a mathematically proven maximum-throughput schedule. It supplies no new completion-hour forecast.
