Separate owner-issued finite PREPARE/READ grants opt into this kind and exact
trusted pairing. Old R52/R53/R54 grants gain no new right. Normal request input
contains no endpoint/path/credential or uploaded EP payload. Planned thin routes
under /v1/inspection-adoptions: capability, POST plans, GET plans/{plan_id} and
GET intents/{operation_id}, with explicit dossier query for reads, Bearer and
X-Forge-Inspection-Audience. Private local CLI provides owner init/bind/issue/
revoke plus the same prepare/read/original-intent semantics; no offline export.

Known operationID and frozen input are persisted before outbound GET. Reuse
R52 private witness/seal/atomic IO and finite record capacity. Identical replay,
concurrency/lost response/separate Forge and EP Server restarts recover the
original snapshot and proposal; changed same-key input conflicts. Missing or
corrupt initialized storage is not healthy empty history. No second inspection
or proposal is admitted during recovery.

Current own authority/pairing epoch is checked before and after network; no own
authority lock spans EP/socket wait. Protected readback and publication require
current original peer GET and unchanged whole response binding. Denied/expired/
unavailable peer access never exposes the private retained cache as success.
Already shared bytes cannot be withdrawn; no distributed atomic revoke/lock is
claimed. Unknown source changes after capture remain unknown.
