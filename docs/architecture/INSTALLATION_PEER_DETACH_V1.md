# Own-installation peer detach v1

The installer can remove the selected Forge runtime's project-independent EP installation binding through `forge installation-peer detach` and authenticated `POST /v1/installation-peer/detach`. `forge installation-peer detach-status` and `GET /v1/installation-peer/detach/{operation_id}` recover the exact durable terminal receipt without writes. Existing instance-admin authentication is required; Workspace grants cannot authorize these routes. The product independently resolves the real OS operator and existing active G001 binding. No request supplies operator, installation, runtime or a filesystem path.

The exact closed request contains `operation_id`, `expected_binding_id`, and positive integer `expected_configuration_revision`. `installation-peer show` and configure receipts expose the revision. Schema 46 preserves existing schema-45 binding bytes and assigns revision 1 to an existing binding, or revision 0 without one. Configure and detach advance a durable generation; a reused binding ID never reuses an earlier revision.

Stored live configuration must have the closed typed shape, positive integer operator binding version, exact canonical JSON bytes and normalized peer fields. Coherent malformed configuration is denied before any transition, preventing a terminal receipt whose private basis cannot be recovered.

Before any transition Forge checks the current runtime marker/schema, active operator/installation, exact binding and generation and verified canonical configuration digest. The runtime mutation lease and one immediate SQLite transaction cover deletion of only `installation_peer_configuration`, revision advance, immutable receipt insertion and audit. Failure rolls everything back. No external EP request or secret resolver is used. Installation operator binding, project execution host, provider configuration, projects, Missions and credential references remain owned by their existing services.

The immutable operation also retains the original configuration document and revision as a separate private basis. Recovery validates its closed shape and own-instance binding, recomputes the original configuration digest from that basis, and strictly validates canonical request types; the returned receipt never includes the private credential reference. This basis survives normal operational reset even if operational logs are purged. Current operator verification occurs inside the immediate effect transaction so revocation and detach are serially ordered.

The receipt binds operation, runtime, installation, operator binding version/fingerprint, binding, before/after configuration revisions, original configuration digest, canonical context/request digest and canonical receipt digest. Identical retry returns the exact receipt; changed request or current operator context refuses. A historical retry after reconfiguration returns its historical receipt and cannot remove the new binding. An absent operation, stale precondition or corrupt receipt fails closed. Status opens storage read-only and verifies the same context and exact receipt. It does not infer that the runtime remains detached after a later configuration; current `show` provides that independent readback.

Normal operational reset preserves configuration, generation and detach history and blocks their mutation during maintenance. Installed update owns schema migration; detach does not migrate an older runtime. CLI failures use the existing nonsecret error envelope. No credential value is read, returned or removed; helper-owned credential cleanup and EP's separate detach receipt belong to the installer orchestration.

Source acceptance covers real canonical storage, CLI and HTTP authentication/shape, exact replay/lost response/restart, generation reuse, foreign/revoked operator, busy runtime, transactional rollback, migration, preservation and tamper denial. Delivery requires independent Quality/Security, full validation/coverage, protected source/finalization, official product release readback and exact published artifact installed isolation. This producer delivery grants no live installation mutation or L4 adoption; LANE_1 owns its subsequent consumer qualification.
