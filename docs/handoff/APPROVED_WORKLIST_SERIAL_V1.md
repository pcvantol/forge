## Claims and recovery

The existing runtime/bootstrap leases and workset revision CAS serialize
starters. Narrow same-thread/PID/inode lease reuse allows nested canonical
runtime composition; default acquisition and other processes/threads stay busy.
One durable claim binds installation/generation/workset/subject, exact observed
eligibility/release revisions, expiry and predecessor evidence. The finite
allowance is consumed once before canonical replayable intake. Intake and policy
recovery retain the actual allocator identity; no second queue/planner exists.

Current operator authority, decisions, release/expiry/hold, exact Candidate,
dependency proof, generation and allowance are checked again immediately before
start. Current source head is read through the existing public owner path. A
proven same-repository predecessor delivery can update input Truth without
changing the already approved next Candidate/scope. EP still owns current
qualification, Action admission, capacity, execution and cleanup.

A process killed after claim/intake/policy but before start reopens the same
Mission. A process killed in an already claimed provider attempt remains an
exact-lineage ambiguity hold when no durable provider result exists; it cannot
blindly repeat the provider or replace the Mission to refresh budgets. Lost EP
response follows existing persisted request/identity recovery without another
POST. Unrelated quiescent failed planning attempts retain existing canonical
capacity treatment. New advisory Candidates never join the committed selector.
